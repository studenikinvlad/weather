# Telegram Task Manager

Python-бот с русским интерфейсом внутри Telegram. Подтверждение задачи превращается в постоянную карточку: статусы, сроки, исполнитель и чеклист обновляются редактированием этого сообщения. PostgreSQL поддерживается для эксплуатации, SQLite работает без дополнительных сервисов. Docker, веб-интерфейса и LLM API нет.

## Личный кабинет и команды

Откройте `/cabinet` или «🏠 Личный кабинет / Команды» в личном чате с ботом.

1. **Личное** — задачи видны только вам. **Создать команду** — введите название; вы станете владельцем. Общая Telegram-группа для такой команды не требуется.
2. В команде нажмите **Пригласить** и передайте ссылку сокоманднику. Ссылка открывает бота; человек отдельно подтверждает вступление и получает роль участника. Срок ссылки — 7 дней, лимит — 100 вступлений. В базе хранится SHA-256 токена приглашения.
3. **Участники → человек** — посмотреть его задачи; владелец может назначить роль администратора или участника. Администратор управляет задачами, приглашает людей и исключает обычных участников. Роль владельца защищена.
4. **Новая задача → Назначить → Создать** — исполнитель получает карточку в своём личном чате. Её изменения синхронизируются с исходной карточкой и открытыми копиями остальных участников. Повторные изменения не создают новую копию каждый раз.
5. **Задачи команды** — общий список; **Мои задачи** — назначения вам в выбранном пространстве. Списки, поиск и счётчики ограничены выбранным пространством. Переключение сохраняется после перезапуска; уже открытый черновик сохраняет исходную команду.

При исключении участника его незавершённые задачи остаются без исполнителя. Открытые личные карточки закрываются при синхронизации; все кнопки проверяют доступ сразу. Существующие приглашения отзываются, чтобы исключённый человек не вернулся по старой ссылке. Администратор может выпустить новую. При добровольном выходе отзываются только приглашения уходящего участника. Владелец не может выйти, пока остаётся владельцем.

Пользователь может состоять в нескольких командах. Личное пространство нельзя открыть команде или пригласить туда другого человека. Удалить уже увиденные/сохранённые пользователем копии данных Telegram не позволяет; после исключения новая информация ему не передаётся.

Используется стандартная [ссылка запуска Telegram-бота](https://core.telegram.org/bots/features#deep-linking), без сайта и формы регистрации.

## Запуск

На этом компьютере окружение и Xray уже установлены, подписка сохранена в `.env`. Самостоятельный запуск из PowerShell:

```powershell
& "C:\Users\stude\.codex\.chatgpt-projects\g-p-6aa4dd65fb3c8191b5c4fc52201fef9d\start-bot.cmd" restart
```

`restart` корректно останавливает предыдущий экземпляр этого проекта, затем запускает бота и Xray в текущем окне. Оставьте окно открытым. Остановка — `Ctrl+C` либо `stop-bot.cmd` из папки проекта. Без аргумента `restart` уже работающий бот не дублируется. Codex для запуска не требуется.

В обычной командной строке Windows (cmd.exe) используйте ту же команду без начального `&`.

Нужен Python 3.12+ и токен от **@BotFather**. Команды выполняются из корня проекта.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m app
```

Заполните `BOT_TOKEN` в `.env`. Если установлен Python 3.13/3.14, используйте соответствующую версию вместо `py -3.12`. Если активация запрещена политикой PowerShell:

```powershell
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m app
```

### Linux / macOS

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните BOT_TOKEN в .env любым редактором
python -m app
```

Альтернативная команда: `python main.py`. SQLite автоматически создаёт `taskbot.db` и таблицы. `.env` и относительный путь базы зависят от рабочей папки — запускайте из корня проекта. Без токена приложение выдаёт понятную ошибку; подключиться к Telegram без него невозможно.

## Xray: VLESS через gRPC/TLS

В `.env` задаются `XRAY_ENABLED=true`, секретная HTTPS-ссылка `XRAY_SUBSCRIPTION_URL`, локальный `XRAY_PORT` (по умолчанию 18080) и `XRAY_PROFILE_INDEX=-1` для автоматического выбора. Индекс 0..N закрепляет конкретный профиль. Xray запускается дочерним процессом, HTTP-прокси слушает только `127.0.0.1`. Оба клиента Telegram — aiogram и raw httpx — используют этот прокси. Системный прокси, маршруты Windows и другие приложения не меняются. Это туннель Telegram-трафика бота; база данных и первоначальное получение подписки идут обычным соединением.

Поддерживаются plain/base64-подписки с VLESS/gRPC/TLS, включая `sni`, `authority`, `serviceName`, `alpn`, `fp`. TLS-сертификаты проверяются. Неподдерживаемые профили пропускаются; исходный протокол не заменяется. Сначала проверяется последний рабочий профиль, затем остальные. При недоступности всех профилей запуск прекращается: автоматического выхода Telegram напрямую нет. Если процесс Xray завершается во время работы, бот останавливается. При временном сетевом сбое polling повторяет соединение через тот же прокси; для выбора другого сервера можно перезапустить бота.

Подписка обновляется при запуске, если кэш старше суток. Если сервер подписки недоступен, используется кэш той же ссылки. Смена ссылки не использует старый кэш. Принудительное обновление:

```powershell
.venv\Scripts\python -m app.vpn --refresh
```

Проверка туннеля отдельно от бота (при остановленном боте, чтобы освободить порт):

```powershell
.venv\Scripts\python -m app.vpn --check
```

На новом Windows x64 компьютере после установки Python-зависимостей:

```powershell
.venv\Scripts\python scripts\install_xray.py
```

Установщик загружает официальный релиз [XTLS/Xray-core](https://github.com/XTLS/Xray-core/releases), сверяет SHA-256 и извлекает только известные файлы в `tools/xray`. На Linux/macOS установите соответствующий официальный бинарник самостоятельно и укажите `XRAY_BINARY`. В этой среде проверена версия v26.3.27, которую вернул официальный release API при установке.

Подписка, UUID и конфигурация находятся только в `.env`/`.runtime`; они исключены из Git. Логи Xray отключены, ошибки подключения не содержат адреса подписки и ключей. Не публикуйте эти файлы. Остановка через `Ctrl+C`/`stop-bot.cmd` завершает дочерний Xray; после принудительного завершения процесса ОС может потребоваться остановить оставшийся экземпляр Xray перед повторным запуском.

Интеграция использует [gRPC transport Xray](https://xtls.github.io/en/config/transports/grpc.html) и [proxy session aiogram](https://docs.aiogram.dev/en/latest/api/session/aiohttp.html). Реальные `getMe` через aiogram и raw-клиент проверены через туннель.

## Настройка BotFather

- `/setinline` — задайте подсказку «Опишите задачу».
- `/setjoingroups` — `Enable`.
- `/setprivacy` — `Disable`, чтобы получать обычный текст в группах. При необходимости добавьте бота в группу заново после изменения.
- `/setcommands` — вставьте список ниже. При запуске бот тоже устанавливает команды.

```text
start - Главное меню
task - Новая задача
today - Сегодня
my - Мои задачи
search - Поиск
projects - Проекты
cabinet - Личный кабинет
teams - Мои команды
team - Текущая команда
help - Помощь
```

В группе назначьте бота администратором: это необходимо для надёжной проверки членства и получения обновлений реакций/участников. Для проектов-тем включите форум и дайте `can_manage_topics`. Право удаления сообщений позволяет убирать служебные запросы.

Администратор группы первым выполняет `/start` и становится владельцем команды. Остальные вступают по ссылке-приглашению из личного кабинета. Для команды, связанной с Telegram-группой, дополнительно требуется членство в самой группе. Ранее зарегистрированные участники сохраняются при обновлении. Только зарегистрированные участники появляются в списке назначения.

## Повседневная работа

- Сообщение или `/task Купить домен завтра 14:00` → черновик → «Создать задачу».
- `Саша сделай договор завтра до 16 высокий приоритет` распознаёт зарегистрированного Сашу, срок и приоритет. При совпадении имён назначение остаётся пустым; используйте `@username`.
- `#Sales` выбирает существующий проект Sales. Сообщения внутри темы получают проект темы.
- Reply с `задача`, `+task` или `задача @username` создаёт черновик из исходного сообщения. Сохраняются native reply, идентификаторы источника и ссылка, если она доступна.
- Пересланное сообщение предлагает создание с кнопками назначения/срока. Доступные forward metadata сохраняются; скрытых авторов бот не раскрывает.
- «В работу» → «Готово» → «Вернуть»; «На проверку», архив, название, описание, проект и удаление — в «Ещё». Удаление мягкое, с подтверждением.
- «Передать» — участники с пагинацией по 8. Можно взять свободную задачу на себя.
- «Срок» — сегодня, завтра, пятница, без срока или ForceReply. Ответьте именно на запрос бота. Для дня без времени применяется 18:00; «пятница» в пятницу — следующая пятница.
- Чеклист: до 12 пунктов по 120 символов. Название до 240, описание до 1200 — карточка помещается в лимит Telegram.
- Ответ на карточку сохраняется как комментарий. Документы, фото и другие вложения хранятся как Telegram `file_id` и связь с сообщением, без скачивания. Вложения исходной задачи доступны через reply/источник.
- ✅ → готово, 👀 → в работу, 🔥 → повысить приоритет. Только новые реакции конкретного участника на зарегистрированную карточку, с проверкой прав и переходов. NEW → DONE запрещён: сначала возьмите в работу. Анонимные реакции игнорируются.
- `/search текст`, `/search #184`, `/today`, `/my`, `/projects`, `/team` — командный интерфейс.

В группе используется команда этой группы. В личном чате действует выбранное в кабинете пространство. Командную карточку можно открыть и редактировать из своего личного чата с учётом прав. Парсер детерминированный; неполную интерпретацию можно исправить до подтверждения. `ParserProtocol` позволяет подключить другой парсер.

Сроки хранятся в UTC. Ввод использует часовой пояс пользователя, начально из `TIMEZONE`. Общая карточка явно показывает часовой пояс из конфигурации.

## Права

OWNER/ADMIN меняют все задачи команды. MEMBER меняет назначенные ему задачи и созданные им свободные задачи, может взять свободную задачу и комментировать. После передачи другому исполнителю автор с ролью MEMBER теряет право редактирования.

Владелец назначает роли: `/role @username ADMIN` или `/role @username MEMBER`. Выход из группы удаляет членство. Перед действиями с групповой задачей членство также проверяется через Telegram, включая открытие из личного чата. `OWNER_TELEGRAM_ID` открывает служебную `/health`, но не обходит изоляцию команд и не подтверждает наличие Premium.

Callback содержит глобальный ID задачи, показываемый номер уникален внутри команды. Проверяются формат, длина, база, членство, права и принадлежность кнопки карточке. Черновик привязан к создателю, чату и сообщению. Повторное подтверждение не создаёт вторую задачу. Черновики и ForceReply-запросы сохраняются в базе и действуют 24 часа.

## Проекты и дополнительные возможности Telegram

`/project Sales` или «Проекты → Новый проект» создаёт проект. В форуме сервис пытается создать тему. Если Telegram отклоняет создание из-за отсутствия возможности/прав, сохраняется обычный проект. Карточка проекта позволяет переименовать, закрыть и открыть тему; ручные изменения тем синхронизируются по service messages.

При изменении проекта задачи карточка остаётся в исходной теме: перенос существующего Telegram-сообщения с сохранением идентификатора недоступен.

`ENABLE_PERSONAL_TOPICS=true` создаёт пять персональных тем, если `getMe.has_topics_enabled` сообщает о поддержке. Включите соответствующий режим у BotFather. Это темы для организации задач; карточки автоматически между фильтрами не переносятся. При недоступности используется обычный чат.

`ENABLE_PREMIUM_UI=true` добавляет стиль кнопки «Готово»; `PREMIUM_DONE_EMOJI_ID` задаёт необязательный custom emoji. При отказе Telegram используется стандартная клавиатура. Флаг приложения не выдаёт Telegram-права.

`TelegramCapabilities` предпочитает aiogram, отсутствующие методы вызывает через raw `TelegramApiClient` на httpx. Есть таймауты, ошибки, ограниченные повторы 429 с `retry_after`. Неоднозначные сетевые ошибки отправки не повторяются автоматически во избежание дубликатов. HTTP URL с токеном не логируются.

`TelegramChecklistService.send_checklist/edit_checklist` подготовлены для Business connection. Основной чеклист работает без Business; нативные Business-чеклисты автоматически из обычных карточек не отправляются.

Business handlers сохраняют connection, сообщения, редактирования и удаления. Удалённое содержимое очищается. Это слой для будущего сценария подтверждения владельцем; автоматического анализа/создания задач из клиентской переписки нет.

Inline mode возвращает карточку-заготовку. Ответ «задача» превращает её в черновик там, где установлен бот. До подтверждения заготовка не является командной задачей. Inline-поиск не реализован; поиск работает внутри чата.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api), [createForumTopic](https://core.telegram.org/bots/api#createforumtopic), [sendChecklist](https://core.telegram.org/bots/api#sendchecklist), [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton), [aiogram polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html).

## PostgreSQL без Docker

Установите PostgreSQL обычным установщиком для своей ОС, запустите службу и в `psql` под администратором выполните:

```sql
CREATE USER taskbot WITH PASSWORD 'replace-with-a-strong-password';
CREATE DATABASE taskbot OWNER taskbot;
```

В `.env`:

```dotenv
DATABASE_URL=postgresql+asyncpg://taskbot:YOUR_PASSWORD@localhost/taskbot
```

Спецсимволы пароля должны быть URL-encoded. Затем:

```bash
python -m alembic upgrade head
python -m app
```

PostgreSQL-схема при старте автоматически не создаётся. Не выполняйте `downgrade base` на рабочей базе — это удаляет таблицы.

Для пустой SQLite тоже можно выполнить `alembic upgrade head`. Если исходная версия до личных кабинетов создала базу автоматически без истории Alembic, остановите бота, сделайте резервную копию и после проверки исходной схемы:

```bash
python -m alembic stamp 7dac96df25a0
python -m alembic upgrade head
python -m alembic check
```

Новая миграция `b84c2e19a601` сохраняет существующие задачи и участников, отмечает старые личные пространства и добавляет приглашения/выбор команды. Для свежей базы, которую автоматически создала уже эта версия, после проверки схемы можно выполнить `alembic stamp b84c2e19a601`, затем `alembic check`. Не используйте `stamp` для пропуска реальных изменений схемы. При будущих обновлениях: резервная копия, затем `python -m alembic upgrade head`. `create_all` не изменяет существующие колонки. Откат новой миграции запрещён, если существуют команды без привязанной группы, чтобы не потерять данные.

## Напоминания и эксплуатация

Scheduler проверяет базу раз в 30 секунд. Напоминания: за сутки, за час, при наступлении срока. Флаги: `REMINDERS_ENABLED`, `REMINDER_DAY`, `REMINDER_HOUR`, `REMINDER_OVERDUE`. Изменённые флаги отдельных видов применяются к новым/изменённым срокам; `REMINDERS_ENABLED=false` останавливает всю отправку после перезапуска.

Напоминания создаются в транзакции с задачей/сроком; `(task_id, kind)` предотвращает дубли в базе. Завершение/удаление снимает их. Рестарт не создаёт их заново, отправленные отмечены. При ошибке доставки повтор через 5 минут. После простоя не отправляются предупреждения «за сутки/час» для уже просроченных задач.

Изменения задачи сначала фиксируются в базе. При временном отказе редактирования `card_dirty` оставляет карточку в очереди синхронизации. Удалённая вручную карточка не заменяется незаметно новой; ошибка остаётся в журнале.

**Один процесс на токен и базу.** Polling, локальная блокировка и scheduler рассчитаны на один экземпляр. Для горизонтального масштабирования нужны распределённые блокировки/выбор лидера и отдельная доставка outbox. Exactly-once доставка Telegram не гарантируется: авария между отправкой напоминания и фиксацией `sent_at` может вызвать повтор. Обычный рестарт повторных reminder-записей не создаёт.

Для постоянного запуска подходят systemd или Планировщик заданий Windows: укажите абсолютный путь к Python из `.venv` и рабочую папку проекта. `Ctrl+C` закрывает worker и соединения. `USE_WEBHOOK=true` выдаёт ошибку конфигурации: эта версия использует polling.

Логи JSON в stderr: следите за `update_failed`, `card_sync_deferred`, `reminder_delivery_failed`. SQLite резервируйте штатным backup API или при остановленном боте с учётом WAL; PostgreSQL — через `pg_dump`. Ограничьте доступ к базе и копиям: там задачи, Telegram ID, комментарии и Business-переписка. Истёкшие черновики и мягко удалённые задачи сохраняются до обслуживания базы.

Тесты без токена проверяют даты/DST, парсер, права, переходы, HTML, callback, сервисы, рестарт напоминаний, поиск, raw API fallback/retry, реальный dispatcher aiogram с поддельным Telegram API, миграции upgrade/check/downgrade. Среда проверки: Python 3.14 и aiogram 3.31. PostgreSQL SQL можно получить без сервера командой `python -m alembic upgrade head --sql` с PostgreSQL URL.

Бот подключён к реальному Telegram через polling. Сценарии кабинета, приглашений, ролей и двух пользователей проверены через реальный dispatcher с поддельным Telegram API; миграция — на заполненной SQLite и копии рабочей базы. Сервер PostgreSQL и специальные Business/Premium-права аккаунта не проверялись.
